# Selbrume — registre déterministe des prompts d'assets

## Statut et mode d'exécution

Ce registre couvre les 154 modules historiques et le kit de 24 pierres à deux étages désormais déclarés dans `ATLAS_LAYOUTS.json`. Chaque ligne historique contient le statut observé, le hash brut accepté et, le cas échéant, une raison de rejet factuelle; les itérations exceptionnelles et le nouveau kit reçoivent en plus un registre détaillé sous le tableau. Les hashes normalisés et d'atlas sont consignés dans `ASSET_PROVENANCE.md`. Le mode utilisé est le built-in `imagegen`; les seize modules `stone_chain_*` actifs proviennent de la planche finale de remplacement 4×4 documentée ci-dessous. La planche originale 4×4 et sa correction coins/caps 2×2 sont conservées comme provenance historique avec le statut `superseded`. Les autres modules suivent le mode historique d'un module, état ou frame par appel. Aucun fallback de génération ni changement silencieux de modèle n'a été utilisé.

Les cartes complètes citées comme références sont `composition-only` et ne doivent jamais être recopiées ni intégrées comme underlays. Le chroma est **`#ff00ff` pour les atlas forêt, marais et `ts_selbrume_cliff_stone_chain_v1`**; les six autres atlas utilisent **`#00ff00`**. La couleur clé est interdite dans le sujet.

## Construction byte-for-byte du prompt final exact

Le prompt final d'une ligne `r` est la concaténation UTF-8 suivante, dans cet ordre exact, avec un unique saut de ligne LF entre chaque segment et aucun espace ajouté ou retiré. Les valeurs sont les cellules littérales du registre, sans mise en forme Markdown. Il n'existe aucun texte implicite à inventer :

```text
FINAL_PROMPT(r) =
BASE_PROMPT
+ "\nModule ID: " + r.id
+ "\nAtlas ID: " + r.atlas
+ "\nPrimary request: Create exactly one isolated sprite depicting " + r.subject + "."
+ "\nRequired normalized footprint: " + r.footprint + "; anchor: " + r.anchor + "."
+ "\nState or edit instruction: " + r.state_edit_instruction
+ "\nReference images in exact priority order: " + r.references + ". Full-map references are composition-only."
+ "\nChroma key: Use exactly " + r.chroma + " as a perfectly uniform background and do not use that color in the subject."
+ "\nModular geometry invariant: " + GEOMETRY_INVARIANT(r)
+ "\nAcceptance constraints: one subject only; fully visible; no text, logo, watermark, character or Pokémon; no additional floor or scenery outside the requested module; no cast shadow outside the module footprint; crisp silhouette readable at native size."
```

`GEOMETRY_INVARIANT(r)` est résolu exactement par le premier cas correspondant ci-dessous. Les coordonnées en pixels sont celles de la sortie normalisée, origine `(0,0)` en haut à gauche. Pour une ligne d'édition, les images d'entrée sont, dans l'ordre : la sortie acceptée nommée dans `state_edit_instruction`, puis les fichiers de `references`. Pour une ligne autonome, les images d'entrée sont uniquement les fichiers de `references`. Cette règle détermine les entrées de l'appel; elle ne modifie pas `FINAL_PROMPT(r)`.
